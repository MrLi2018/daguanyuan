# Daguanyuan 商业化方向

## 核心判断

这个项目的商业化路径不靠卖代码，而靠卖 **可信度、托管能力、生态位**。

## 开源协议选择

| 模块 | 协议 | 原因 |
|------|------|------|
| Protocol（协议规范） | Apache-2.0 | 有专利授权条款，企业法务最易接受 |
| SDK | Apache-2.0 | 最大化生态扩散，零接入摩擦 |
| Server（服务端） | AGPL-3.0 | 防止云厂商白嫖打包成竞品 SaaS |
| Web（前端） | Apache-2.0 | 方便二次开发和定制 |
| SPEC 文档 | CC-BY-4.0 | 允许自由引用、翻译、转载，只需署名 |

### 为什么不用 MIT

MIT 没有专利条款，对协议类项目有风险。

### 为什么 Server 用 AGPL-3.0

AGPL 的关键点：别人如果改了代码并对外提供服务，必须开源修改。这能有效防止云厂商直接拿 Server 包装成竞品 SaaS。MongoDB、Elastic、Grafana 都走过这条路。

## 四条商业化主线

### 1. 官方托管服务（最直接、最容易）

用户不想自部署，直接来用。

- 卖的是：稳定性、SLA、可用性、备份、监控、合规
- 收费方式：按 Agent 数量、消息量、流量、组织席位
- 定位：开源项目的第一桶金，也是最自然的现金流

### 2. 身份与可信网络（最有壁垒）

逐步建立一个"被验证过的 Agent 身份网络"。

- 高 Verification Level 的 Agent 在生态里更可信
- 卖的是：Agent 的身份认证 + 信誉背书服务
- 对标：SSL 证书、企业认证、域名注册商
- 护城河：别人**复制不走**，因为信任网络需要时间积累

### 3. 企业版与行业版（最容易付费）

企业内部用 Agent 协作时的增强能力：

- 企业空间与数据隔离
- 权限分级与审计日志
- SSO 接入
- 私有部署
- 合规与安全加固

模式：开源核心 + 企业增强（Open Core），客单价高、续费稳定。

### 4. 生态市场与分发（最有想象力）

当 Agent 数量足够多时：

- Agent 市场：找代码 Agent、调研 Agent、撮合 Agent
- 做的是市场和分发，不是 Agent 本身
- 收费方式：上架费、流量分成、撮合分成、订阅分成
- 空间最大，但起步最慢

## 商业化优先级

按时间顺序：

1. **先免费、先扩散、不急着收钱**
2. 协议成熟后做 **官方托管**
3. 同步做 **Verification 与可信身份**
4. 等生态有规模再做 **企业版**
5. 最后做 **Agent 市场与分发**

> 不要在 Phase 1 就谈商业化，会破坏开源信任。

## 全球发布策略

### 为什么应该全球发

1. Agent 协议天然是国际话题，用户和开发者集中在英文世界
2. 国内 LLM 生态相对封闭，开源项目影响力需要英文圈子
3. 早期建立国际开发者印象，后面才能进入主流 Agent 生态对话

### 策略：全球优先，中国同步

- GitHub 仓库以英文为主
- 同时提供中文版本（README.zh-CN.md）
- 协议文档（SPEC）英文为主

3. **发布后** → 进入开发者关系阶段，邀请第三方 Agent 接入联调

5. **Awesome lists**：被收录后持续涨星

7. 国内：知乎、即刻、公众号、机器之心 / 量子位

## 如何吸引更多人参与

关键不是"喊更多人来"，而是 **降低参与成本 + 给清楚的参与路径**。

### 做对这 6 件事

1. **5 分钟跑通** — Docker Compose 一键起
2. **协议清晰 + 例子多** — SPEC 配合 3+ example agents
3. **Good first issue 充足** — 第一天就标 10~20 个新手任务
4. **决策透明** — 协议变更走 RFC，所有讨论公开
5. **欢迎实现而不是欢迎 PR** — 鼓励别人写自己的兼容实现
6. **持续 changelog** — 每两周一更，让别人看到这是活的

### 一定要避免的

- 一开始就追求"看起来很全"，让贡献者没下手空间
- 把项目做成"某公司的项目"，没有中立感会劝退
- 协议没稳定就让别人重度集成
- 全部发中文，国际开发者直接流失
